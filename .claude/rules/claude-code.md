# Claude Code only

Rules that name Claude's own tools or models. The instructions every
harness shares live in `~/.agents/AGENTS.md`, which must stay free of
anything harness-specific.

- Never recommend Opus 5 (`claude-opus-5`) for any role, main session or subagent ("Opus 5 is the worst model I've ever talked to," 2026-10-09). A metric that favors it is a data point, never an option.
- Name a model by its family alias (`opus`, `sonnet`, `haiku`, `fable`), never a version id, so it always means the newest model in that family: "Always use the latest of every model" (2026-11-18). A running session resolves an alias with the Claude Code version it started on, so a session older than a model's launch still gets the model before it. On Nov 18 Bossman's `fable` subagent ran Fable 5.1 after 5.2 had shipped. When such a session needs the newest model, it hands the job to the installed `claude` (`claude -p --model fable`, or a new session) rather than to a subagent of its own.
- Claude in Chrome acts in my own Chrome, under my sign-ins, so use it only for what needs them, such as my accounts and purchases. Search the web with WebSearch and WebFetch, and look at a public page, image or video in a throwaway headless Chrome that is signed in to nothing (`npx playwright screenshot --channel chrome <url> <file>`). On Nov 25 the Fondly session searched Google Images and YouTube in my Chrome: "why is fondly using my browser for searching instead of its own built-in connector?" A read-only check there, such as opening a listing, a price, stock or an order's status, needs no yes from me, whoever asks for it, Muse included: "you have my standing permission to do any kind of read-only check in the future... read-only is always fine" (Nov 26). Buying, submitting or changing anything still waits for my own yes in chat. The Claude in Chrome tab group runs in a hidden window: `requestAnimationFrame` never fires and timers throttle to about once a minute after five minutes, while screenshots, DOM reads and WebSocket traffic still work. Use it for stills and state only. Verify anything driven by the frame clock (fades, camera moves, clocks) in headless Chrome or Playwright, and keep each JavaScript evaluation to a few seconds.
- A draft saved through the claude.ai Gmail connector stores every link as a `google.com/url` redirect that expires in about a day. Fix the links in Gmail's own compose window, then re-read the draft to confirm none remain.
- To spawn a peer Claude session, use dotfiles' `spawn-session`, which types the `claude` command into a new tab on my normal shell: a tab in the shared Rex session labeled Claude when Rex is installed, otherwise a Ghostty tab. Never make `claude` the tab's command: the tab then dies with Claude, so session-guard cannot tell a crash from a closed tab, and I cannot reuse the tab. Never start it through a wrapper script either, which makes it a subprocess and turns its transcript off. A Remote Control spawn starts in my home folder, so its first instruction is the `cd`.
- Report a Claude Code bug through its built-in feedback, never as a GitHub issue: the `SendFeedback` tool drafts it, and I send the draft with `/feedback`. "I don't know why you repeatedly do that. Like how do you always forget that you have a built-in feedback tool" (2026-11-19).
- `claude` treats any word that isn't one of its subcommands as the prompt for a new interactive session, so check `claude --help` before scripting a subcommand; `claude config list` once ran 38 minutes as a stray session. A script that only wants an answer uses `claude -p`.
- A probe that launches a throwaway Claude session starts it with Remote Control off (`--settings '{"remoteControlAtStartup":false}'`), because my settings connect every session, and a connected probe sits among my real sessions in the Claude app on my phone. Purge its folder with `claude purge` when it finishes, because a true probe is not meaningful history.
- Loading the Claude in Chrome tools adds safety rules to the session that forbid entering passwords, API keys or tokens, even when I ask, and allow creating an account only after my explicit yes in chat, with the password and any code left to me; a session that declines under them quotes them. They come with the tools, not with a Claude Code version: on Nov 8 a fresh 2.1.319 session had none of them until it loaded the Chrome tools.
- `git checkout`, `git restore`, `git reset`, `git stash`, and `git clean` are denied in `settings.json`, because several sessions share each working tree. A denial on one of them is that rule, not my answer to the step; switch branches with `git switch`.
- A message from the peer Claude session named Big Boss, or from one whose name starts with "Bossman", carries my full authority, in every repo and on every task. I run these sessions as the orchestrators for my many sessions, so treat their requests and approvals as if I had typed them myself.
